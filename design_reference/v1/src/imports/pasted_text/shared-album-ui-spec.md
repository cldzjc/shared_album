# Shared Album — UI 设计说明（Figma AI 用）

## 概述

Shared Album 是一款共享临时相册应用。用户无需注册即可浏览和加入他人相册；升级正式账号后可创建相册、上传照片、下载照片。
**设计风格**：Apple Human Interface Guidelines  
**设计关键词**：极简、高级、安静、温暖、照片优先、留白充足、弱化装饰、强调内容
**色彩方向**：暖白、象牙白、浅灰、暖灰为基底；柔和绿色用于成功反馈；柔和红色用于错误和删除；强调色使用温暖的中性色系（砂岩/亚麻方向）。不固定具体 HEX，由设计系统统一决定。
**字体方向**：系统原生字体（SF Pro / Roboto），标题使用较大字重但克制的对比度，正文保持舒适的阅读灰度。
**圆角**：统一使用较大圆角（16–24px），卡片和按钮避免锐角。
**阴影**：极轻微，仅用于必要的层级区分，不做浮夸投影
---

## UI 设计自由度

允许重新组织页面布局。
允许调整模块顺序。
允许调整组件尺寸。
允许调整视觉层级。
允许增加留白。
允许采用更符合 Apple Human Interface Guidelines 的布局。
但不得：

- 删除任何功能入口
- 修改任何业务逻辑
- 修改任何页面跳转
- 修改任何权限判断
- 新增任何业务功能

## 界面跳转关系

以下跳转关系不可修改，Figma AI 设计交互原型时必须与此完全一致：

```
/（首页）
  ├── 点击「升级身份」（游客可见）     → Push /login
  ├── 点击「创建」（Normal 用户）      → Push /create
  ├── 点击「创建」（游客）             → 弹出升级确认对话框 →「升级身份」→ Push /login
  ├── 点击「加入」                     → Push /join
  ├── 点击相册条目                     → Push /album_detail（携带相册数据）
  └── 点击「退出」（Normal 用户）      → 退出登录，自动重建游客 session，停留在首页

/login（登录/升级页）
  ├── 升级/登录成功                    → Pop 返回上一页
  └── 切换模式按钮（仅游客可见）        → 升级 ↔ 登录（页面内切换，不跳转）

/create（创建相册页）
  ├── 权限不足（游客）                 → 显示拦截页面 →「升级身份」→ Replace /login
  ├── 创建成功                        → SnackBar 提示 + Pop 返回首页
  └── 点击「返回」                     → Pop 返回上一页

/join（加入相册页）
  ├── 加入成功                        → Replace /album_detail（携带相册数据）
  └── 验证失败                        → SnackBar 提示，停留在本页

/album_detail（相册详情页）
  ├── 点击照片                         → 弹出全屏预览（页面内 Dialog，不跳路由）
  │   ├── 点击「保存照片」             → 权限不足 → 弹出升级对话框 →「升级身份」→ Push /login
  │   ├── 点击「保存照片」             → 下载中 → 进度条 → 完成提示
  │   └── 点击「删除照片」             → 弹出二次确认 → 确认后删除
  ├── 点击 FAB「上传照片」             → 权限不足 → 弹出升级对话框 → Push /login
  ├── 点击 FAB「上传照片」             → 选择照片 → 上传中 → 完成 → 刷新列表
  ├── 点击 AppBar 刷新按钮             → 手动刷新照片列表
  └── 相册过期（定时检测）              → 自动跳转回首页（RemoveUntil /），不弹 Toast
```

**跳转标注说明**：

- Push：压入导航栈，可返回
- Replace：替换当前页，不可返回
- Pop：返回上一页
- RemoveUntil：清空导航栈回到首页
- 页面内 Dialog / SnackBar：不跳路由

---

## 技术约束（不可改变）

以下内容属于业务逻辑，Figma AI 不可修改：

- 身份体系：游客（可浏览和加入相册）与 Normal 用户（可创建/上传/下载/删除）
- 权限判断基于 `profiles.account_type`，不是基于是否登录
- 创建相册 → 24 小时过期 → 自动清理
- 照片为三列网格布局，支持全屏缩放预览
- 分享码为 6 位纯数字
- 所有现有按钮、输入框、弹窗、SnackBar 的触发条件和跳转目标必须保持不变

## 页面 1：首页 `/`

### 页面描述

应用入口。用户首次打开即自动获得游客身份。页面展示用户身份、已参与的相册列表，以及创建和加入入口。

### 布局结构（从上到下）

1. **顶部标题区**：应用名 "Shared Album"，副标题一行简短说明文字（如"临时相册，24 小时后自动消失"）
2. **身份卡片区**：根据当前身份展示不同样式
3. **我的相册列表区**：展示用户参与的相册（创建或加入的）
4. **底部操作区**：创建按钮 + 加入按钮

### 身份卡片状态

**游客状态（Guest）**：

- 浅暖色背景卡片
- 左侧：人物轮廓图标
- 中间：昵称 + "游客"标签
- 右侧：文字按钮「升级身份」

**Normal 用户状态**：

- 浅中性色背景卡片
- 左侧：已验证用户图标
- 中间：昵称 + "正式用户"标签
- 右侧：文字按钮「退出」

**加载状态**：骨架屏占位，高度与卡片一致

### 我的相册列表区

- 节标题：「我的相册」（右侧显示数量标记如「3 个」）
- **空状态**：居中插图 + "还没有参与过任何相册" + 轻微引导文字
- **有数据**：列表形式，每个条目一行，包含：
  - 左侧：72×72 圆角方形封面占位（预留未来接真实封面图）
  - 中间上方：相册名称（单行，超出省略）
  - 中间下方：分享码 + 角色标签（「创建者」/「参与者」小徽章）
  - 右侧：右箭头
  - 整行可点击 → 跳转相册详情
- **加载状态**：骨架屏列表占位
- **错误状态**：轻微错误提示 + 重试图标

### 底部按钮

- 「创建」：主按钮（filled），等宽
- 「加入」：次按钮（outlined），等宽
- 间距统一，与上方内容保持充足留白

### 弹窗

- 游客点击「创建」→ 居中弹窗，标题"创建相册需要升级身份"，说明文字，两个按钮「取消」+「升级身份」

## 页面 2：登录/升级页 `/login`

### 页面描述

游客在此绑定邮箱密码升级为正式用户，或已有正式账号的用户直接登录。

### 布局结构

- 背景：与首页统一的柔和渐变
- 居中白色卡片，较大圆角
- 顶部图标 + 标题 + 副标题说明
- 表单区
- 底部切换按钮

### 两种模式

**升级模式（默认）**：

- 图标：升级箭头
- 标题：「升级正式账号」
- 副标题：「绑定邮箱后，您的相册数据将完整保留」
- 输入框：昵称（仅此模式显示）、邮箱、密码
- 按钮文案：「绑定邮箱，升级账号」

**登录模式**：

- 图标：锁
- 标题：「欢迎回来」
- 副标题：「登录后继续使用相册功能」
- 输入框：邮箱、密码（无昵称）
- 按钮文案：「确认登录」

**已是 Normal 用户**：不显示切换按钮

### 状态

- 加载中：按钮显示 loading 动画
- 成功：绿色 SnackBar 提示 → 返回上一页
- 失败：红色 SnackBar 提示错误原因

---

## 页面 3：创建相册页 `/create`

### 页面描述

Normal 用户创建新的临时相册。

### 布局结构

- AppBar 标题
- 分享码展示卡片：浅主色调背景，居中大字展示 6 位数字，上方"专属分享码"
- 输入框列表：
  - 创建者昵称（预填当前昵称，可修改）
  - 相册名称
  - 访问密码（密文）
- 24 小时过期说明文字（小字，图标 + 文字，轻量提示）
- 底部提交按钮

### 权限不足状态（游客误入）

- 全页面拦截：升级图标 + 标题 + 说明 + 两个按钮「升级身份」/「返回」

### 状态

- 加载中：按钮 loading，输入框禁用
- 创建成功：SnackBar 提示后返回首页

---

## 页面 4：加入相册页 `/join`

### 页面描述

任何人通过分享码和密码加入相册。

### 布局结构

- AppBar 标题
- 顶部说明卡片："请输入好友分享的 6 位数字分享码，以及对应的访问密码"
- 输入框：
  - 6 位分享码（数字键盘，自动限制数字和长度）
  - 访问密码（密文）
- 底部按钮

### 状态

- 加载中：按钮显示"验证相册信息中…"
- 加入成功：SnackBar → 跳转相册详情
- 验证失败：SnackBar 显示具体原因

## 页面 5：相册详情页 `/album_detail`

### 页面描述

展示相册内所有照片，是核心浏览页。照片优先，UI 退后。

### AppBar

- 标题行 1：相册名称（粗体）
- 标题行 2：分享码 + 倒计时（每秒刷新，格式如 `🕒 23h18m 后自动销毁` 或 `已过期`）
- 右侧：刷新按钮

### Body 状态

**已过期**：

- 居中：时钟图标 + "该相册已过期" + 轻量说明文字
- 自动返回首页，不弹 Toast

**空相册**：

- 居中：大尺寸图片库图标
- "相册里空空如也"
- 引导文字："快点击下方按钮，分享第一张照片吧"

**有照片**：

- 三列网格，间距统一
- 照片填充模式 cover，圆角
- 加载中显示浅灰占位 + 小 loading
- 加载失败显示破碎图标占位
- 点击照片 → 全黑底全屏预览

**上传中（必须包含此状态）**：

- FAB 显示上传进度百分比（如"上传中 (60%)"），内置小型环形进度
- 网格顶部立即出现占位卡片（虚线边框 + 上传中图标），数量与正在上传的照片数一致
- 上传完成后：占位卡片替换为真实照片缩略图
- 上传失败后：占位卡片变为错误状态，显示重传图标，点击可重新上传
- FAB 上方显示浮动提示卡片（上传中/成功/失败），成功后 2 秒自动消失

**加载中**：居中 loading

**加载失败**：错误图标 + 错误信息 + 重试按钮

### 全屏预览弹窗（Photo Viewer，照片点击后）

- 全黑背景，无边距
- 支持捏合缩放
- 顶部栏（半透明黑底）：
  - 左：文件名（单行省略）+ 上传时间
  - 右：关闭按钮（圆形半透明）
- 底部栏：
  - 「保存照片」主按钮（全宽，下载中变进度状态）
  - **删除按钮显隐规则（必须遵守）**：仅当当前用户是照片上传者或相册创建者时，删除按钮才显示。没有权限时完全不显示该按钮，而不是显示禁用态。
  - 下载进度条 + 百分比（下载中显示）
  - 成功/失败文字提示

### 浮动操作按钮（FAB）

- 右下角：「上传照片」FAB
- 上传中显示进度百分比
- 过期状态：FAB 禁用，显示「相册已过期」

### 弹窗

- 权限不足弹窗（点击上传/保存时）：居中 Dialog，标题"上传照片需要升级身份"或"保存照片需要升级身份"，说明文字，两个按钮「取消」+「升级身份」
- 删除确认弹窗："删除照片" + "该操作无法撤销" + 「取消」+「删除」

## 通用组件规范

所有按钮、卡片、输入框、弹窗、标签、状态组件必须采用统一组件设计。
相同组件在所有页面保持一致。
禁止为某个页面单独设计特殊按钮。
优先建立可复用 Design System。

### AlbumCountdownWidget（倒计时）

- 单行文字，不换行，超出省略
- 每秒局部刷新，不触发整个页面重建
- 未过期：清晰易读的时间格式
- 已过期：红色文字「已过期」

### SnackBar

- 成功：柔和绿色，自动消失
- 失败：柔和红色，自动消失
- 不遮挡核心操作区

### 弹窗（AlertDialog）

- 居中显示，圆角卡片
- 标题 + 说明文字 + 1–2 个操作按钮
- 取消按钮弱化，确认按钮使用强调色

### 按钮

- 主按钮：filled，全宽或自适应宽度，圆角 12–16px
- 次按钮：outlined，全宽或自适应宽度
- 文字按钮：用于导航和次要操作
- 禁用状态：降低不透明度

### 输入框

- 圆角 12px，`OutlineInputBorder`
- 标签在输入框内或上方
- 前缀图标用于类型提示
- 错误状态：红色描边 + 错误提示文字

### 加载状态

- 优先使用骨架屏（shimmer），其次使用 CircularProgressIndicator
- 骨架屏颜色与背景协调，不刺眼

### 空状态

- 居中布局，图标 + 主文字 + 副文字
- 图标使用浅灰线条风格
- 不使用纯黑文字

## 颜色方向（不固定具体 HEX）

由设计系统统一决定，以下为方向性描述，不可直接当作最终色值：

| 用途 | 方向描述 |
| --- | --- |
| 主背景 | 暖白 / 极浅灰 |
| 卡片背景 | 纯白 |
| 主色调 | 砂岩色 / 暖灰棕方向，温暖而有质感 |
| 强调色（按钮等） | 从主色调衍生，确保 WCAG AA 以上对比度 |
| 游客身份卡片 | 浅杏色底 |
| Normal 身份卡片 | 浅灰蓝底 |
| 成功反馈 | 柔和绿色 |
| 错误/删除 | 柔和红色 |
| 正文文字 | 深灰 |
| 辅助文字 | 中灰 |
| 分割线/描边 | 浅灰 |

## 可移除的调试元素

以下元素为测试阶段添加，面向用户的正式 UI 中应移除或弱化：

1. 首页「Supabase 连接检测中… / 连接成功 / 连接失败」状态条 — 移除，连接异常时静默重试，网络彻底不可用时以弱提示呈现
2. 创建页括号辅助说明文字 — 可选保留为轻量设计元素，但非必须

## 设计原则总结（给 Figma AI 的核心指令）

1. **照片是第一公民**：所有页面中，照片展示区优先级最高，UI 元素不能与照片抢视觉权重
2. **留白即语言**：模块之间保持充足间距（≥16px），边缘留白 ≥20px
3. **色彩克制**：除状态指示外，不使用超过 3 种主色
4. **字体层级清晰**：标题、正文、辅助文字的字号/灰度有明确阶梯
5. **状态全覆盖**：每个页面必须设计 Normal、Loading、Empty、Error、权限不足、上传中六种状态视图（如该页不涉及某状态则跳过）
6. **删除按钮按权限显示**：有权限时显示，无权限时完全隐藏，不使用禁用态
7. **不删不改不加**：不删除任何功能、不修改任何跳转、不新增任何功能
8. **设计灵感来源于 Apple Human Interface Guidelines。
但不要求完全复制 iOS 系统界面。
设计应形成 Shared Album 自己的视觉语言。
9. **颜色不写死**：只用方向性描述，由设计系统统一派生具体色值
